IMPORTANT CONCEPTS TO EXPLAIN
----------------------------
1. OOP
   "The application is organized using C# classes and Windows Forms.
    Each major screen is represented by a class, and database access is
    centralized through DbHelper."

2. DATABASE
   "SQL Server is used as the backend database."

3. DbHelper
   "DbHelper contains reusable methods for executing SELECT queries and
    non-result INSERT/UPDATE/DELETE queries."

4. CRUD
   "Company, user and vehicle management implement CRUD operations:
    Create, Read, Update and Delete."

5. RELATIONSHIP
   "VehicleManage is related to CompanyManage through VehicleComId and
    CompanyID. Booking stores the booked vehicle and company information."

6. LOGIN
   "Admin/Driver credentials are checked from ManageUser, while passenger
    credentials are checked from SignUp."

7. SEARCH
   "Passenger searches vehicles using starting point, destination and date."

8. BOOKING
   "Ticket price multiplied by ticket count gives the total price, and
    booking data is inserted into the Booking table."

9. DRIVER
   "The driver's assigned vehicles are found using the driver's UserId."

LIKELY VIVA QUESTIONS
---------------------

Q: What language did you use?
A: C#.

Q: What framework?
A: Windows Forms with .NET Framework 4.7.2.

Q: Which database?
A: Microsoft SQL Server.

Q: Why did you create DbHelper?
A: To reuse database connection and query execution logic instead of
   repeating the same connection code in every form.

Q: What is CRUD?
A: Create, Read, Update and Delete.

Q: What is a primary key?
A: A column that uniquely identifies each record in a table.

Q: Why is CompanyID used in VehicleManage?
A: It identifies which company owns/manages the vehicle and allows the
   application to join vehicle and company information.

Q: How does passenger booking work?
A: Passenger searches a route, selects a vehicle, enters ticket count,
   the application calculates total price, and then inserts the booking
   record into Booking.

Q: How does the driver see assigned vehicles?
A: The application filters VehicleManage by driverId matching the logged-in
   driver's UserId.

Q: What happens if the database is unavailable?
A: DbHelper catches the exception and returns an error message, which the
   form displays.

Q: What would you improve in a production version?
A:
- Use parameterized SQL queries to prevent SQL injection.
- Hash passwords instead of storing plain text.
- Store the connection string in configuration.
- Add stronger validation and transaction handling.
- Add proper role/permission management.
